# Архитектура

Этот документ описывает архитектурное устройство приложения Remote Transmission Desktop Client.

## Обзор

Remote Transmission Desktop Client следует принципам чистой архитектуры с чётким разделением ответственности между различными слоями приложения. Архитектура спроектирована так, чтобы быть сопровождаемой, тестируемой и гибкой.

## Архитектурные слои

Приложение организовано в следующие слои:

### 1. Слой предметной области (Domain Layer)

Слой предметной области содержит основную бизнес-логику и сущности приложения. Он независим от других слоёв и фреймворков.

**Ключевые компоненты:**
- `domain/torrent.go`: Определяет модель торрента и связанные интерфейсы
- `domain/config.go`: Сущности конфигурации
- `domain/session_stats.go`: Сущности статистики сессии

Слой предметной области определяет интерфейсы, которые реализуются инфраструктурным слоем, следуя принципу инверсии зависимостей.

### 2. Слой приложения (Application Layer)

Слой приложения оркестрирует поток данных между слоями предметной области и инфраструктуры. Он содержит варианты использования приложения.

**Ключевые компоненты:**
- `application/torrent_service.go`: Сервис для управления торрентами и реализации бизнес-правил
- Управление соединением с автоматическим переподключением и обработкой тайм-аутов

Этот слой координирует работу сущностей предметной области и инфраструктурных сервисов для выполнения конкретных задач, таких как добавление торрентов, управление путями загрузки, контроль соотношения отдачи и обработка проблем соединения.

### 3. Инфраструктурный слой (Infrastructure Layer)

Инфраструктурный слой обеспечивает реализацию интерфейсов, определённых в слое предметной области, и интеграцию с внешними сервисами. Он содержит конкретные реализации, такие как клиент Transmission API, хранилище конфигурации и сервисы локализации.

**Ключевые компоненты:**
- `infrastructure/transmission_client.go`: Клиент Transmission RPC API
- `infrastructure/config_service.go`: Управление конфигурацией приложения
- `infrastructure/localization_service.go`: Сервис локализации
- `infrastructure/encryption_service.go`: Безопасное хранение учётных данных

### 4. Слой пользовательского интерфейса (User Interface Layer)

UI слой отвечает за взаимодействие с пользователем. Он построен с использованием React и связан с приложением Go через фреймворк Wails.

**Ключевые компоненты:**
- React-компоненты для отображения UI
- Контексты для управления состоянием приложения
- Хуки для инкапсуляции логики и взаимодействия с бэкендом

## Поток данных

1. **Пользовательское действие** инициирует событие в UI слое.
2. **Слой пользовательского интерфейса** вызывает функции, предоставляемые `app.go` через привязки Wails.
3. **`app.go`** координирует действие через слой приложения.
4. **Слой приложения** обрабатывает запрос, используя сервисы и сущности из слоя предметной области.
5. При необходимости **слой предметной области** использует инфраструктурный слой для взаимодействия с внешними системами.
6. Результаты передаются обратно в UI слой, который обновляет представление для пользователя.

## Ключевые паттерны проектирования

- **Инверсия зависимостей**: Слои предметной области и приложения определяют интерфейсы, которые реализуются инфраструктурным слоем, что делает их устойчивыми к внешним изменениям.

- **Сервисы приложения**: Инкапсулируют логику вариантов использования и оркестрируют работу сущностей предметной области.

- **Репозиторий**: Абстрагирует хранение и извлечение данных от конкретных реализаций хранилища.

- **Фабрика**: Используется для создания экземпляров компонентов, особенно в инфраструктурном слое.

- **Клиент-серверное взаимодействие**: Взаимодействие с сервером Transmission посредством REST API.

- **Контексты и провайдеры React**: Для управления глобальным состоянием приложения и предоставления данных и функций компонентам.

- **Хуки React**: Для инкапсуляции логики, переиспользуемой разными компонентами.

## Архитектура фронтенда

Фронтенд следует компонентно-ориентированной архитектуре с использованием React и TypeScript:

- **Компоненты**: Переиспользуемые UI компоненты в `frontend/src/components`
- **Контексты**: React Context API для управления состоянием в `frontend/src/contexts`
- **Пользовательские хуки**: Общая логика и управление состоянием в `frontend/src/hooks`
- **CSS модули**: Инкапсуляция стилей для компонентов

## Взаимодействие между фронтендом и бэкендом

Взаимодействие между React-фронтендом и Go-бэкендом осуществляется посредством фреймворка Wails:

1. Go-функции экспортируются через параметр `Bind` в `main.go`
2. TypeScript-привязки генерируются в `frontend/wailsjs/go/`
3. Компоненты фронтенда вызывают эти привязки для выполнения Go-функций

## Обработка ошибок

Приложение реализует комплексную стратегию обработки ошибок:

- Ошибки предметной области определены в слое предметной области
- Инфраструктурные ошибки отображаются на ошибки предметной области при необходимости
- Сервисы приложения обрабатывают и переводят ошибки для UI
- Локализованные сообщения об ошибках предоставляются пользователю

## Управление конфигурацией

Конфигурация приложения обрабатывается через:

- **Сервис конфигурации**: Загружает и сохраняет конфигурацию в JSON-файл
- **Сервис шифрования**: Безопасно хранит конфиденциальные данные (например, пароли)
- **Слой приложения**: Проверяет и применяет конфигурацию
- **UI**: Предоставляет интерфейс для редактирования настроек

## Локализация

Система локализации поддерживает множественные языки:

- **Файлы JSON**: Хранят строки перевода для каждого языка
- **Сервис локализации**: Загружает и управляет строками перевода
- **Контекст локализации React**: Предоставляет переводы компонентам React
- **Функция translate**: Преобразует ключи в локализованные строки с поддержкой параметров

## Соображения по безопасности

Приложение реализует несколько мер безопасности:

- **Безопасное хранение учётных данных**: Пароли хранятся в зашифрованном виде
- **Безопасные соединения**: Поддержка HTTPS для подключения к серверу Transmission
- **Корректная обработка входных данных**: Проверка и санация всех входных данных перед использованием
- **Безопасное управление файлами**: Корректная обработка файловых операций для предотвращения уязвимостей

## Расширяемость

Архитектура разработана для поддержки будущих расширений:

- **Новые функции торрентов**: Легко добавляются через расширение сервисов приложения и интерфейса
- **Дополнительные языки**: Система локализации легко расширяется для новых языков
- **Новые темы**: Система тем допускает добавление пользовательских тем
- **Поддержка платформ**: Архитектура позволяет добавлять зависимые от платформы функции при сохранении основной логики
