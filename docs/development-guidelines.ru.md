# Рекомендации по разработке Transmission Client

В этом документе изложены основные рекомендации, принципы и лучшие практики по разработке и поддержке проекта Transmission Client. Следование этим рекомендациям обеспечивает постоянное качество кода, снижает количество типичных ошибок и помогает поддерживать архитектурную целостность приложения.

## Основные принципы разработки

1. **Соблюдение чистой архитектуры**
   - Строго поддерживайте разделение между слоями (domain, application, infrastructure, UI)
   - Зависимости всегда направлены внутрь (UI → Application → Domain)
   - Слой предметной области должен оставаться свободным от внешних зависимостей

2. **Обработка ошибок**
   - Определяйте ошибки как переменные (`var ErrSomething = errors.New("description")`) вместо строковых констант
   - Используйте `errors.Is()` и `errors.As()` для проверки ошибок вместо сравнения строк
   - Оборачивайте ошибки контекстом при передаче их вверх по стеку вызовов (`fmt.Errorf("context: %w", err)`)
   - Возвращайте значимые, практические сообщения об ошибках

3. **Управление конфигурацией**
   - Всегда проверяйте, инициализирована ли конфигурация перед её использованием
   - Предоставляйте разумные значения по умолчанию для необязательных параметров конфигурации
   - Проверяйте значения конфигурации на ранних этапах
   - Используйте строгую типизацию для объектов конфигурации

4. **Организация кода**
   - Сохраняйте фокус файлов на единой ответственности
   - Группируйте связанную функциональность в пакеты
   - Последовательно следуйте соглашениям об именовании в Go и React
   - Размещайте тесты рядом с тестируемым кодом
   - Поддерживайте чёткую иерархию директорий

5. **Документация кода**
   - Документируйте все публичные функции и типы
   - Включайте примеры использования для сложных API
   - Объясняйте «почему», а не только «что» делает код
   - Обновляйте документацию при изменении кода

## Рекомендации по React/TypeScript

1. **Типизация компонентов**
   ```tsx
   // ❌ Избегайте: Неявная типизация
   const MyComponent = ({ text }) => {
       return <div>{text}</div>;
   };
   
   // ✅ Делайте: Явная типизация пропсов
   interface MyComponentProps {
       text: string;
       onClick?: () => void;
   }
   
   const MyComponent: React.FC<MyComponentProps> = ({ text, onClick }) => {
       return <div onClick={onClick}>{text}</div>;
   };
   ```

2. **Управление состоянием**
   ```tsx
   // ❌ Избегайте: Избыточные состояния
   const [firstName, setFirstName] = useState('');
   const [lastName, setLastName] = useState('');
   const [email, setEmail] = useState('');
   
   // ✅ Делайте: Группировка связанных состояний

       firstName: '',
       lastName: '',
       email: ''
   });
   
   // Обновление состояния
   setFormData(prev => ({ ...prev, firstName: 'Новое имя' }));
   ```

3. **Использование хуков**
   ```tsx
   // ❌ Избегайте: Игнорирование зависимостей в useEffect
   useEffect(() => {
       fetchData(userId);
   }, []); // ESLint: React Hook useEffect has a missing dependency: 'userId'
   
   // ✅ Делайте: Указывайте все зависимости
   useEffect(() => {
       fetchData(userId);
   }, [userId, fetchData]);
   
   // Если fetchData меняется, используйте useCallback
   const fetchData = useCallback((id) => {
       // логика загрузки
   }, [otherDependencies]);
   ```

4. **Типобезопасность**
   ```tsx
   // ❌ Избегайте: Слабая типизация

       // Неявно возвращает Promise<void> или Promise<boolean>
       const isValid = await validatePath(path);
       if (!isValid) return;
       await savePath(path);
       return true;
   };
   
   // ✅ Делайте: Явная типизация
   const handleSubmit = async (e: React.FormEvent): Promise<boolean> => {
       const isValid = await validatePath(path);
       if (!isValid) return false;
       await savePath(path);
       return true;
   };
   ```

## Распространённые проблемы и их решения

### 1. Конфигурация не инициализирована

**Проблема**: Использование конфигурации до её инициализации ведёт к разыменованию нулевого указателя.

**Решение**: 
- Всегда проверяйте, инициализирована ли конфигурация (`if config == nil { return ErrConfigNotInited }`)
- Используйте шаблоны инициализации (например, синглтон или фабрику) для обеспечения настройки конфигурации перед использованием
- Рассмотрите использование шаблона `MustInit()` для критически важных компонентов

### 2. Непоследовательная обработка ошибок

**Проблема**: Разные части кода обрабатывают ошибки по-разному, что затрудняет отладку и поддержку.

**Решение**:
- Определите стандартизированные типы ошибок для общих ошибок
- Используйте последовательные шаблоны обёртывания ошибок
- Реализуйте централизованную обработку ошибок на границах между слоями
- Логируйте ошибки с соответствующим контекстом на правильном уровне

### 3. Состояния гонки в управлении состоянием

**Проблема**: Параллельный доступ к разделяемому состоянию приводит к состоянию гонки и непредсказуемому поведению.

**Решение**:
- Используйте мьютексы для разделяемого состояния в Go
- Используйте управление состоянием React для избежания прямых манипуляций с состоянием
- Рассмотрите шаблоны неизменяемых данных
- Используйте атомарные операции, где это уместно

### 4. Зависимости коллбэков в React

**Проблема**: Отсутствие необходимых зависимостей в хуках React ведет к устаревшим замыканиям и труднообнаружимым ошибкам.

**Решение**:
- Всегда указывайте все зависимости в массиве зависимостей
- Используйте ESLint правило `react-hooks/exhaustive-deps`
- Оборачивайте функции с помощью `useCallback` для предотвращения изменений при каждом рендере
- Используйте функциональные обновления для состояний, которые зависят от предыдущих состояний

### 5. Обработка асинхронных операций

**Проблема**: Неправильная обработка асинхронных операций приводит к гонкам данных и утечкам памяти.

**Решение**:
- Используйте механизмы отмены для запросов `fetch`
- Очищайте тайм-ауты и интервалы в эффектах
- Проверяйте, смонтирован ли компонент перед обновлением состояния

### 6. Оптимизация производительности

**Проблема**: Частые ререндеры и неэффективные обновления замедляют пользовательский интерфейс.

**Решение**:
- Используйте `React.memo` для предотвращения ненужных ререндеров
- Мемоизируйте тяжелые вычисления с помощью `useMemo`
- Стабилизируйте функции с помощью `useCallback`
- Перемещайте состояние как можно ближе к тому месту, где оно используется
