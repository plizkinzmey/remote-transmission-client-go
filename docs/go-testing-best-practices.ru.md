# Лучшие практики организации автоматизированных тестов в Go

---

## 1. Структура файлов и пакетов
- Размещайте тесты рядом с тестируемым кодом.
- Имена тестовых файлов должны заканчиваться на `_test.go`.
- Сохраняйте имена пакетов одинаковыми для кода и тестов, чтобы избежать ненужных проблем с видимостью.

## 2. Именование тестовых функций
- Каждая тестовая функция должна начинаться с `Test`.
- Используйте описательные имена: `TestFunctionName_Scenario`.
- Пример:
  ```go
  func TestCreateUser_ValidInput(t *testing.T)
  ```

## 3. Утверждения (Assertions)
- Используйте понятные операторы `if` для сравнения.
- Для лучшей читаемости и отчетности об ошибках рассмотрите использование библиотек, таких как `testify`.
- Всегда предоставляйте полезные сообщения в `t.Errorf` или `t.Fatalf`.

## 4. Подтесты (Subtests)
- Используйте `t.Run` для табличных тестов и логически сгруппированных сценариев.
- Пример:
  ```go
  func TestLogin(t *testing.T) {
      tests := []struct { name string; input string; wantErr bool }{...}
      for _, tt := range tests {
          t.Run(tt.name, func(t *testing.T) {
              // Логика теста здесь
          })
      }
  }
  ```

## 5. Изоляция
- Тесты не должны зависеть от общего изменяемого состояния.
- Используйте логику настройки (setup) и очистки (teardown) внутри каждого теста при необходимости.

## 6. Внедрение зависимостей (Dependency Injection)
- Предпочитайте передачу зависимостей через интерфейсы.
- Это упрощает мокирование и делает тесты более надежными.

## 7. Использование моков (Mocks)
- Реализуйте моки вручную, когда это возможно.
- Для сложных случаев используйте библиотеки, такие как `golang/mock` или `testify/mock`.

## 8. Покрытие тестами (Test Coverage)
- Регулярно запускайте `go test -cover ./...` для отслеживания нетестированного кода.
- Стремитесь к осмысленному покрытию, а не к 100% ради галочки.

## 9. Быстрые и сфокусированные тесты
- Юнит-тесты должны быть быстрыми и сфокусированными.
- Тяжелые операции (база данных, внешние API) относятся к интеграционным тестам.

## 10. Непрерывная интеграция (Continuous Integration)
- Интегрируйте тесты в ваш CI/CD пайплайн.
- Всегда запускайте тесты при каждом push и pull request.

## 11. Полезные утилиты
- Используйте инструменты, такие как:
  - `go test -v` для подробного вывода
  - `go test -coverprofile=coverage.out && go tool cover -html=coverage.out` для визуализации покрытия
  - `gotests` для генерации шаблонных тестовых случаев

## 12. Понятные ошибки
- Проваленные тесты должны сообщать об ошибке как можно раньше и громче.
- Предоставляйте действенные сообщения для ускорения отладки.

## 13. Документация
- Комментируйте сложные тестовые случаи.
- Объясняйте, "почему" тест существует, если это не очевидно.

---

Применение этих лучших практик поможет поддерживать ваш набор тестов Go чистым, поддерживаемым и эффективным!
