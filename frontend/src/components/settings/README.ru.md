# Компонент Settings

## Обзор

Компонент `Settings` предоставляет модальное диалоговое окно для настройки параметров приложения. Он позволяет пользователям управлять деталями подключения, лимитами загрузки/отдачи и путями хранения. Компонент обрабатывает загрузку существующих настроек, валидацию пользовательского ввода, тестирование соединения, сохранение изменений и управление состояниями загрузки/ошибки. Он может отображаться автоматически при первом запуске приложения или открываться вручную пользователем.

## Пропсы (Props)

-   `isOpen` (boolean): Управляет видимостью модального окна настроек.
-   `onOpenChange` (function): Функция обратного вызова, вызываемая при изменении состояния открытия модального окна (например, при закрытии пользователем).
-   `isFirstStart` (boolean, опционально): Если `true`, модальное окно отображается в режиме "первого запуска", предотвращая закрытие до тех пор, пока настройки не будут сохранены и соединение не будет проверено. По умолчанию `false`.

## Использование

```tsx
import { useState } from 'react';
import { Settings } from './Settings';
import { Button } from '@/components/ui/button'; // Предполагается, что компонент Button существует

function App() {
  const [isSettingsOpen, setIsSettingsOpen] = useState(false);
  const [isFirstStart, setIsFirstStart] = useState(checkIfFirstStart()); // Логика для определения первого запуска

  return (
    <div>
      <Button onClick={() => setIsSettingsOpen(true)}>Открыть настройки</Button>
      <Settings
        isOpen={isSettingsOpen || isFirstStart}
        onOpenChange={setIsSettingsOpen}
        isFirstStart={isFirstStart}
      />
      {/* Другое содержимое приложения */}
    </div>
  );
}
```

## Внутренние хуки (Internal Hooks)

Компонент использует несколько пользовательских хуков для управления своей логикой:

-   `useSettingsLoader`: Обрабатывает загрузку начальных настроек с бэкенда и управляет состоянием `isLoading`.
-   `useSettingsState`: Управляет основным состоянием формы настроек, включая объект `settings`, ошибки валидации `errors`, статус соединения (`isConnectionValid`, `connectionErrorMessage`) и ожидающие изменения путей (`hasPendingPathsChanges`). Также предоставляет колбэк `handleSettingsChange`.
-   `useConnectionTester`: Инкапсулирует логику для тестирования соединения с сервером Transmission на основе текущих настроек.
-   `useSettingsSaver`: Управляет процессом сохранения, включая валидацию, взаимодействие с `PathsTab` для изменений путей, вызов бэкенд-функции `SaveAllSettings`, а также обработку состояния `isSaving` и ошибок сохранения.

## Подкомпоненты (Subcomponents)

Настройки организованы по вкладкам:

-   `ConnectionTab`: Для настройки адреса сервера, порта, имени пользователя и пароля.
-   `LimitsTab`: Для установки глобальных и индивидуальных лимитов скорости и соединений.
-   `PathsTab`: Для управления каталогами загрузки и расположениями незавершенных файлов.

## Управление состоянием (State Management)

Основное состояние (`settings`, `errors` и т.д.) управляется внутри хука `useSettingsState`. Состояния загрузки и сохранения (`isLoading`, `isSaving`) управляются соответственно `useSettingsLoader` и `useSettingsSaver`. Общее состояние открытия/закрытия модального окна контролируется извне через пропсы `isOpen` и `onOpenChange`.

## Обработка ошибок (Error Handling)

-   **Ошибки загрузки:** Обрабатываются в `useSettingsLoader` и обычно отображаются как общее сообщение об ошибке в модальном окне.
-   **Ошибки валидации:** Рассчитываются `validateSettings` (используется `useSettingsSaver` и потенциально `useSettingsState`) и отображаются внутри соответствующих вкладок.
-   **Ошибки теста соединения:** Обрабатываются `useConnectionTester` и отображаются рядом с кнопкой теста соединения.
-   **Ошибки сохранения:** Обрабатываются `useSettingsSaver` и отображаются как общее сообщение об ошибке.
-   Сообщения о статусе (загрузка, сохранение, успех, ошибка) часто отображаются с использованием компонента `StatusMessage`.
